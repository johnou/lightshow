# Lightshow

A small PWA for playing seasonal light shows across Philips Hue and compatible Govee lights. Pick lights and a scene, adjust pace and brightness, and optionally play an audio file with brightness reacting to its sound. Shows run on the companion, so you can close the phone app after starting one. Stopping a show leaves the lights at their last color.

## Mac companion app

Install dependencies with `npm ci` and build the local Mac app with `npm run build:mac`, then open `Lightshow.app`. It starts the companion automatically and displays the phone URL and connection code. Keep the app running; closing its window leaves it in the menu bar. Quit it from the menu bar to stop the companion and any show. Stop an existing terminal companion before opening the app, since both use port 4177.

On first launch the app copies existing Hue and Govee settings from this checkout into `~/Library/Application Support/Lightshow` if they are not already present there. It includes its own Node runtime and launches its audio and media helpers using the Lightshow app executable so permissions can be associated with the app. macOS may ask for local network, Screen & System Audio Recording, and Accessibility access for their respective features. The app is locally ad-hoc signed, not notarized; macOS permission behavior needs verification on the target Mac, and rebuilding may require granting permissions again. You do not need to run the terminal companion while using the app.

## Terminal companion

1. Install Node.js 22 or later on a computer on the same network as your lights.
2. Run `npm ci`, then `npm start` in this directory. Leave the companion running.
3. Open <http://localhost:4177> on that computer, or open the deployed GitHub Pages app on the same computer. GitHub Pages may ask for permission to access the local network. To use a phone, follow the instructions below.
4. Under **Connections**, enter your Hue Bridge's private IPv4 address and an existing authorized Bridge username, then connect. For Govee, enable **LAN Control** for each supported device in the Govee Home app, and scan. By default, all available lights are included; switch that option off to choose individual lights. When a show uses all available lights, the companion periodically rechecks and adds them when they come back online. Pick a scene and press play.

Hue requires a Bridge and an existing authorized Bridge username; lights already connected to the Bridge do not need to be paired again. An app needs its own authorization to control the Bridge, even when bulbs are already connected. Bluetooth-only Hue control is not supported. Govee discovery uses multicast UDP ports 4001 and 4002, and control uses port 4003. Not every Govee device supports LAN Control. Discovery can be affected by firewalls, network isolation, and multicast settings. The companion remembers discovered Govee addresses locally and checks them directly on later scans; if an address changes, multicast discovery is needed to find it again. The Govee LAN protocol does not acknowledge commands, so sending successfully does not prove a light changed. This project has not been tested against physical devices.

For faster Hue updates, create an Entertainment area in the Hue app. In Lightshow's Connections, press the Bridge button and select **Enable Hue Entertainment**. Start a new show with every light in that area selected. Lightshow streams to a matching inactive area and controls other selected lights normally; if no area matches or the stream fails, it falls back to normal Hue control. In all-lights mode the area can include known Hue lights that are temporarily unavailable; in manual mode every light in the area must be selected. When music reaction is on, choose **Beat** for the original mode or **Immersive** for different effects across bass, mid and high frequencies and smoother Hue transitions. Both use live audio and estimate changes in energy; they do not have Spotify's song metadata.

The Hue Bridge credential is stored in `.lightshow.json` on the companion computer. It is excluded from Git; keep the file private. By default the companion listens on localhost; `npm run start:lan` enables local-network access protected by a code. It accepts browser requests from its own local origin, `https://johnou.github.io`, and `https://just.johno.it` as applicable. It uses the Bridge's self-signed HTTPS certificate and connects only to a private IPv4 address supplied during pairing. Soundtracks are uploaded to the companion and play through the Mac’s selected audio output; they are stored in a temporary directory during the companion session. For an uploaded track, beat sync requires `ffmpeg` on the companion’s PATH and the track repeats until the show stops. Choose **Mac audio** to react to sound playing on the Mac, including YouTube Music. The first use compiles a small Swift helper using the Xcode command-line tools and requests Screen & System Audio Recording permission on the Mac; it calculates audio levels locally and does not save the captured audio. macOS may require restarting the terminal after permission is granted. The remote play/pause and skip buttons send system media keys to the active player and may require Accessibility access for the helper or terminal. Paste a YouTube Music song, album, or playlist link to open it on the Mac, or save it for later. Depending on browser autoplay settings, starting playback may require a click on the Mac. Lightshow does not yet provide YouTube Music search, library browsing, or queue management. The PWA caches its shell for offline use, but controlling lights still requires the running companion and network.

## Control from a phone

1. Open the Lightshow Mac app, or start the terminal companion with `npm run start:lan`.
2. On a phone connected to the same home Wi-Fi, open the phone address shown in the Mac app or printed in the terminal (for example `http://192.168.1.39:4177`). If multiple addresses are shown, use the one for your home network. This address may change if your router assigns a new one.
3. Enter the connection code shown in the Mac app or printed in the terminal. The code and phone session change every time the companion restarts. Keep the computer and Lightshow app (or terminal companion) running during the show. The Mac prevents idle sleep while the show runs, but closing the lid or manually sleeping it will interrupt playback. Reopen the app to change or stop the show.

The phone address is ordinary HTTP, so the connection code, device commands and session are visible to others who can monitor your local network. Use it only on a trusted network; it is not intended for the internet or guest Wi-Fi. Browsers generally require HTTPS for service workers and installable PWAs, so phone access at this address is a browser experience without offline installation. The GitHub Pages URL runs the companion on the device opening it and cannot directly access the computer's HTTP service from a phone. The Hue Bridge must be reachable from the terminal running the companion; if macOS asks for local network access, allow it.

## GitHub Pages

Push to `main` and set **Settings → Pages → Build and deployment → Source** to **GitHub Actions**. The workflow tests, builds, and deploys the static app to `https://just.johno.it/lightshow/`. GitHub Pages hosts the interface only; run the companion locally as above. The PWA can be installed from a supported browser after its first load.

Run `npm test` and `npm run build` to verify the project. The integration follows the [Hue Bridge getting started guide](https://developers.meethue.com/develop/get-started-2/) and the [Govee LAN protocol documentation](https://github.com/damient/govee-toolkit/blob/main/docs/protocol/lan.md).
